# 2026-10-07

## A1 —— Xaero 路网图层迁移到官方 MapElement 扩展点（完成）

公告栏 `docs/Oct.16.docs/NoticeBoard.md` 上认领并交付 WS-A 的 A1。旧的 `XaeroMapOverlay`
走 Fabric `ScreenEvents` + 反射读 `GuiMap.scale/cameraX/cameraZ`、用单位矩阵盖上去，与 Xaero 地图管线无关，
所以缩放/平移/旋转时会漂。现改为挂在 Xaero 官方扩展点 `WorldMap.mapElementRenderHandler`。

### 关键技术结论（复用价值高）

- **扩展点是 public static 字段**，`add(ElementRenderer)` 也是 public ⇒ **不需要 mixin**。
- **`renderElement` 签名三代不同，且分叉与 Xaero 无关，只跟该 MC 版本可用的渲染类型有关**：

  | 版本 | 图形对象 | 顶点缓冲 |
  |---|---|---|
  | 1.20.1 | `GuiGraphics`（jar 内 intermediary `class_332`） | `MultiBufferSource.BufferSource` |
  | 26.1.x | `MapElementGraphics` | `MultiBufferSource.BufferSource` |
  | 26.2 | `MapElementGraphics` | `xaero.lib.client.graphics.XaeroBufferProvider` |

  踩坑：初版想当然把 26.x 统一写成 `XaeroBufferProvider`，26.1.1 直接报
  `not abstract and does not override`。**签名以 jar 内字节码为准，不按大版本号推断。**
- `XaeroBufferProvider` 嵌套在世界地图 jar 的 `META-INF/jars/xaerolib-fabric-<ver>-1.7.1.jar` 里，
  **只有 26.2 需要**补这份依赖；故 `xaeroLibJar` 设成可选属性。
- **坐标映射**：`screen = (world - anchor) * info.scale * poseScale + poseTranslate`。
  实际渲染时把 pose 按 `1/poseScale` 缩放，使「1 单位 = 1 GUI 像素」，于是净比例就是 `info.scale`——
  这个抵消关系容易看错，写在 `XaeroRoadStroke` 注释里了。
- **默认 `isOnScreen` 用 `getRenderBox*`（反汇编确认），但 box 单位是「常数像素」不随缩放变**，
  表达不了「多少格的折线」⇒ 必须自己覆写成 true，在 Provider 里按世界包围盒裁剪。**不要妄想删掉裁剪缓存。**
- 时机：`mapElementRenderHandler` 要等 Xaero 初始化完才非空 ⇒ 在 `ClientTickEvents` 里轮询注册。

### 类隔离（重要工程约束）

全 mod 只有 `XaeroRegistration` 一个类命名 Xaero 类型（另 `XaeroRoadRenderer/Provider/Reader` 因实现接口而必须引用），
`XaeroLayer`/`Style`/`Element`/`Stroke`/`Context`/`ViewState` 对外部 Xaero 包引用 **0 处**，
用 javap 逐类核对过。Xaero 缺席时不注册、不崩，旧叠加层继续用。

### 本次做的优化

1. 视口记录从「每段每帧」降为「每帧一次」（`XaeroViewState.beginPass()` + `claimRecording()`）。
2. 整张路网的元素列表按 `(database.getMutationStamp(), XaeroRoadStyle.stamp())` 缓存，
   一趟只做包围盒筛选，稳态帧不分配。
3. 加了 `XaeroRoadStyle.stamp()`：配色只存在于 config，不在数据库里，只靠数据库 stamp 会让「改配置颜色」
   要等下次编辑才可见。
4. 补了 `RoadNetworkDatabase.updateSegment` 缺失的 `markDirty()`——它会改 nodeIds/direction/roadId
   但不推进 stamp，而 B1 的空间索引与本项缓存都以 stamp 为失效令牌。（已在公告栏「越界说明」知会 B 线）

### 验证方式（值得记：如何绕开别人的在建改动做验证）

整包 `:XX:compileJava` 被 `nav/` 的在建改动挡住，于是：
用 Gradle **init script** 导出每个版本真实的 `sourceSets.main.compileClasspath` 到文本，
再用对应 JDK（1.20.1→17，26.x→25）**只编本项闭包**：

```
javac -proc:none -cp "$(tr '\n' ':' < /tmp/wf-classpath-_<ver>.txt)" \
      -sourcepath "versions/<ver>/src/main/java:src/main/java" <显式文件列表>
```

注意：`versions/<ver>/src/main/java` 必须排在 `src/main/java` 前面，让版本覆盖优先；
**不要用通配符列文件**，否则会把 1.20.1 的 `XaeroRoadRenderer` 一起带进去 → 重复类。
该仓库根 `src/main/java` 里没有任何 `//#if` 预处理指令，所以可以直接拿原始目录当 sourcepath。

spotless 单文件格式化（避免 reformat 别人的在建文件）：

```
./gradlew spotlessApply -PspotlessIdeHook="$PWD/<file>.java"
```

会就地改写该文件，且只改这一个。（`spotlessJavaCheck` 只打印**第一个**违规文件的 diff，
其余只在 `Violations also present in:` 里列名，所以别指望从日志里拿到自己的 diff。）

## Web 导航「一直 No Route」根因与修复

用户反馈点图/开始导航持续报 No Route。排查后端 `NavigationSession.start()`：失败码有
`DESTINATION_NOT_NEAR_ROAD`/`START_NOT_NEAR_ROAD`/`NO_ROUTE`/`NO_ROAD`。
- `NAV_SNAP_RADIUS` 默认 32 格（`WayfarerConfigs.Generic.NAV_SNAP_RADIUS`）；
  `LocationSnapper.nearestNodes` 只吸**已有节点**，不投影到路段中线 → 点在道路线上但离节点 >32 格（节点稀疏/点偏）
  就报 `DESTINATION_NOT_NEAR_ROAD`。`updatePlayer` 每 tick 用 `client.player` 真实坐标更新（`WayfarerClient.java:139`），
  且 HTTP server 与 client 共用同一 `NAVIGATION_SESSION` 单例，故起点吸附本身正常。
- **修复**（`LocationSnapper.java`）：`nearestNodes` 在没有节点命中时，兜底遍历所有路段、把点投影到最近路段中线，
  若投影距离 ≤ radius 则返回该路段两端节点作为吸附候选。直接根治「点道路线却吸不上」导致的 No Route；
  对密集路网（节点命中）不触发扫描，性能无回归。`compileJava` 已验证通过。
- **前端**（`app.js`）：新增 `routeErrorHint(code)` 把后端失败码翻成中文（离道路太远 / 路网不连通等），
  `startNavigation` 与 `planRoute` 的失败 toast 改用它，便于区分是吸附问题还是路网不连通。
- 若修复后仍报 `NO_ROUTE`：说明路网拓扑不连通（路口处两条路没合并成共享节点），需在编辑器里做 intersection/merge，
  属数据问题而非代码 bug。

## Web 编辑器：新增「合并近节点」按钮（一键修路口连通 + 连通块诊断）

用户报"只能导航到同一道路"——点 A 路能导航到 A 路另一点，跨道路（如到 B 路）就 NO_ROUTE。
排查确认：**代码层跨道路完全支持**（GraphSearch 是全图 A*，mergeNodes 会把两条路的端点接成共享节点），
根因是用户数据里路口没真正共享节点。典型误区：merge 工具选了同一条路上的相邻节点（只是缩短路），
或路口只是视觉交叉但没共享节点。用户明确要求"给个按钮，一键扫描节点、合并水平距离<1的对、再跑连通块检查报数量"。

### 实现
- `RoadNetworkDatabase.mergeNearbyNodes(threshold)`：并查集把所有**水平距离(x,z) < threshold**（默认 1.0，**忽略 y**）
  的节点对合并，每组保留 id 最小的作代表，返回合并掉的节点数。
- `RoadNetworkDatabase.countConnectedComponents()`：基于 segment 内相邻节点边做弱连通分量统计，
  返回 (components, isolated, nodeCount)；孤立节点 = degree 0。
- `WayfarerHttpServer` 新增 `POST /api/nodes/merge-nearby`（读可选 body.threshold 默认 1.0；调上面两方法，
  saveToDisk，回 JSON: mergedNodes/components/isolatedNodes/nodeCount）。
- 前端：编辑模式工具栏新增「合并近节点」按钮（`#tool-merge-nearby`，edit-only），调接口后 loadData 并 toast 报告。
- i18n 补 `toolbar.mergeNearby.*` 中英（title/label/working/result）；`:1.20.1:compileJava` 通过（漏 import HashMap 已补）。

### 用法 / 注意
- 进编辑模式 → 点「合并近节点」→ 弹："合并 X 个重合节点 · 当前 Y 个连通块 · Z 个孤立节点（共 N 个节点）"。
  若 Y 仍 > 1 且 Z 多，说明还有没接上的路口需要继续修。
- 阈值 1.0 忽略 y：**立交桥/隧道上下层水平投影重合但应断开的场景会被误合并**，保持阈值小即可；
  若要更稳的"只接几何交叉"逻辑，后续可改 buildGraph 做按需交叉连接（不改持久数据）。

## Web 导航：点"路径节点/路段"无反应的根因与修复

用户报导航模式下点道路节点/路段没反应（"为什么导航不让我点路径节点"）。排查：导航模式下点**空白地图**
走 `onMapClick → openPointInfo` 弹信息卡；但点**节点 marker / 路段 line** 本身是它们自己的 Leaflet click 处理器
先触发（`stopPropagation` 挡掉地图点击），而那里写的是 `if (appMode !== 'edit') { clearSelection(); return; }`——
把点击直接吞掉，既不弹信息卡也不选中，故"点了没反应"。

### 修复（app.js）
- 节点 marker 的 `marker.on('click')` 守卫改为：导航模式 `openPointInfo(e.latlng); return;`（点节点弹信息卡）。
- 4 处路段 `line.on('click')` 守卫同步改为：导航模式 `openPointInfo(e.latlng); return;`。
- `onNodeClick`/`onSegmentClick` 内的 `appMode!=='edit'` 守卫保留（它们只会被编辑模式走到，导航模式已提前短路）。
- `node --check` 通过。效果：导航模式点任意处——空白 / 节点 / 路段——都弹统一的信息卡（直线距离 + 附近道路 + 「到这去」）。
