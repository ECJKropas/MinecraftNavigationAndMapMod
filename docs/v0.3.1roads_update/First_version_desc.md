### 一、最终数据模型（三层完全解耦）

为了同时支持导航（图论）和美观渲染（样条），数据分为三层，互不污染：

```json
{
  "nodes": {
    "n_001": { "x": 100, "z": 200, "y": 64, "cornerType": "AUTO" },
    "n_002": { "x": 120, "z": 200, "y": 64, "cornerType": "SHARP" }
  },
  "segments": [
    { 
      "id": "seg_001", 
      "nodeIds": ["n_001", "n_002", "n_003"], 
      "roadNameId": null 
    }
  ],
  "roadNames": [
    { "id": "road_001", "name": "中山路", "color": "#FFFFFF", "segmentIds": ["seg_001"] }
  ]
}
```

- **Node（节点）**：只存坐标和拐角类型（`SHARP`折线 / `ROUND`弧线 / `AUTO`自动判断）。
- **Segment（路段）**：存**有序的节点ID列表**（长度≥2）。导航只取首尾节点做图连接，渲染取全部节点画线。
- **RoadName（道路名）**：纯粹的标签，一个名字可对应多个不连续的路段（解决一条长路被路口切碎的问题）。

### 二、录制交互与状态机（玩家操作流）

纯客户端依赖玩家指令，设计三个核心按键，逻辑清晰：

| 按键 | 功能 |
| :--- | :--- |
| **`R`** | **开始/结束录制**。按下开始记录起点节点；再次按下结束录制，触发全局拓扑修正。 |
| **`G`** | **强制插入节点**。在当前位置强行打点（用于路口、匝道分合流，即使角度没变）。 |
| **`T`** | **切换拐角模式**。在录制中按此键，将当前最新节点的 `cornerType` 在 `SHARP/ROUND/AUTO` 间循环切换（给玩家手动纠错的最终手段）。 |

**录制状态机**：
1. `IDLE` → 按 `R` → 记录起点节点，进入 `RECORDING`。
2. `RECORDING` → 玩家行走：
   - 检测到**朝向角变化 > 15°** 或 移动距离 > 8格 → **自动记录节点**。
   - 在记录节点的瞬间，调用**“弦长检测算法”**（见下文第四节）自动标定该节点的 `cornerType`。
3. `RECORDING` → 按 `G` → 强制记录当前节点（`cornerType` 默认为 `AUTO`）。
4. `RECORDING` → 按 `R` → 记录终点节点，结束录制，**立即执行全局拓扑合并**（见下文第三节）。

### 三、自动修正十字路口 & 偏差吸附（核心算法）

解决你担心的“-50到50”与“0到5”在原点相交却不自知的问题。**只在录制结束时触发一次**，节省性能：

**算法流程（针对新生成的所有路段，与旧路段比对）**：
1. **遍历比对**：取新路段的每一段子线段（`[P_i, P_{i+1}]`），与所有旧路段的每一段子线段进行**二维叉积相交检测**（忽略Y轴）。
2. **计算精确交点**：若相交，算出数学交点坐标 `(x, z)`。
3. **节点吸附（去偏差）**：
   - 在现有全局 `nodes` 中查找离该交点 **2.5格以内** 的节点。
   - **若找到**：直接将新、旧线段在此处的端点坐标修正为那个已存在的 `NodeId`（消除手抖偏差）。
   - **若未找到**：创建一个新节点 `Node_new`，位置为交点坐标。
4. **拓扑切分（自动挂接）**：
   - 将包含此交点的**旧路段**从中间切断（一分为二），并把 `Node_new` 插入其中。
   - 将包含此交点的**新路段**从中间切断，也把 `Node_new` 插入其中。
   - 此时，两条路通过 `Node_new` 在拓扑图上**真正连通**，导航自动生效。

> 此算法等效于“在路网中埋入一个十字路口节点”，全程无需玩家按键。

### 四、直角/锐角 vs 曲线弯道 的精准识别（弦长检测）

区分“MC方正转角”和“自然曲线”的算法，在**自动记录节点**时执行：

- 维护一个临时缓冲区，存放玩家最近 **1.5秒** 内的坐标轨迹（约20个点）。
- 当触发角度变化（记录节点）时，取缓冲区的**第一个点A** 和 **最后一个点B**。
- 计算 **弦长** `d = A.distanceTo(B)`（即转向起点到转向终点的直线距离）。
- **判定逻辑（硬阈值）**：
  - 若 `d <= 2.5` 个方块（玩家近乎原地转身） → 判定为 **`SHARP`**（渲染时不启用样条，画尖锐折线）。
  - 若 `d >= 4.5` 个方块（玩家绕了大弯） → 判定为 **`ROUND`**（渲染时启用Catmull-Rom样条，生成平滑弧线）。
  - 介于中间 → 保留为 `AUTO`，交由玩家按 `T` 键手动修正。

### 五、渲染策略（分段绘制，直曲分离）

在 `WorldRenderEvents` 中绘制路网时，不要一股脑全样条，按节点类型分段渲染：

1. 遍历 `Segment` 的 `nodeIds` 列表 `[P0, P1, P2, P3, P4]`。
2. 逻辑：
   - 从 `P0` 开始，判断 `P1` 的 `cornerType`。
   - 若 `P1` 是 `SHARP`：**断开连接**，画直线 `P0 -> P1`，再画直线 `P1 -> P2`（呈现锋利拐角）。
   - 若 `P1` 是 `ROUND`：将 `P0, P1, P2` 三个点传入 Catmull-Rom 算法，生成20个插值点，画出平滑弧线。
3. **视觉反馈**：节点处用**小圆球**标记，`SHARP` 显示红色，`ROUND` 显示蓝色，方便玩家实时检查并随时按 `T` 纠正。

### 六、纯客户端存储方案

- **路径**：`FabricLoader.getInstance().getConfigDir().resolve("你的模组名/roads.json")`。
- **IO策略**：使用 `Gson` 或 `Fabric API` 自带的 `JsonHelper`。
- **触发保存**：每次结束录制（按 `R`）并完成拓扑修正后，**自动执行序列化写入**。
- **加载**：游戏启动时（`ClientTickEvents.START`）或按快捷键（如 `L`）手动加载 JSON 文件。
