## 二、需修正或澄清的问题（Must fix）

### 1. **版本支持范围不明确**
- **问题**：PRD 目标中提出“三版本同步支持”（1.20.1 / 26.1.1 / 26.2），但 MVP 中 P2（Xaero Mixin）为 Should，P1 仅涉及浏览器端。若 P2 延迟，则游戏内路网叠加可能无法在所有版本同步交付，与目标冲突。
- **建议**：明确 P2 是否必须作为 MVP 的一部分；若否，则应修改目标表述，或拆分版本支持计划（例如 P1 仅支持浏览器端，P2 再覆盖三版本）。

### 2. **Xaero 依赖版本未锁定**
- **问题**：设计文档中提及“锁定 Xaero 支持版本”，但未列出具体的 Xaero 地图版本号（如 24.4.0、25.1.0 等）。不同 MC 版本对应不同 Xaero 版本，且 Xaero 有多个变体（世界地图、小地图）。
- **建议**：在文档附录中明确支持矩阵（MC版本 ↔ Xaero WorldMap 版本 ↔ 推荐Mod版本），并提供版本检测和自动禁用逻辑。

### 3. **API 契约缺失**
- **问题**：仅提及 `/api/roads/geojson` 端点，未定义请求/响应结构、HTTP 方法、状态码、错误码等。这对前端开发和联调测试不利。
- **建议**：在设计文档中增加“API 接口规范”章节，包含示例 JSON 和错误场景处理。

### 4. **游戏内图层控制 UI 位置模糊**
- **问题**：提到“在 Xaero 大地图侧边栏或 Wayfarer 设置界面中增加图层标签页”，但未选定方案。Xaero 侧边栏控件有限，与 Wayfarer 设置耦合可能增加开发难度。
- **建议**：明确初期方案（例如仅通过 Wayfarer 配置菜单控制可见性，不侵入 Xaero UI），避免 Mixin 与 Xaero UI 组件冲突。

### 5. **性能指标测试条件不足**
- **非功能需求**：Web 页面加载 ≤2s（500条道路），游戏内帧率下降 ≤5%。但未说明测试环境（硬件、数据规模、视口内道路数量），难以验证。
- **建议**：定义基准测试环境（例如：i7-10700K, 16GB, RTX2060, 500条平均长度2000格的道路，视口内约200条），并指定测量方法。

## 三、建议优化项（Nice to have）

### 1. **数据模型冗余字段**
- `RoadPath.style` 字段可能冗余，因为 `classification` 已可映射至配色。若需支持用户自定义样式，可保留；否则建议简化，避免数据存储膨胀。
- **建议**：明确 `style` 是否为可覆盖配置，若仅作为默认配色依据，可移至配置文件。

### 2. **LOD 简化策略未细化**
- 设计文档提到“视口裁剪 + LOD 简化”，但未说明算法（如 Douglas-Peucker 阈值）和阈值设定。建议在开发时参考行业实践，并记录在技术笔记中。

### 3. **P3 种子离线渲染风险**
- 种子渲染为可选，但若未来采用，可能涉及大量计算和存储。建议在 P3 设计时单独评估，本次可仅作为探索项。

### 4. **用户验收测试标准缺失**
- 用户故事中虽有验收标准，但未形成独立的 UAT 清单。建议补充一页简明的 UAT 用例（如“打开地图→看到分级道路→点击弹出信息→切换图层……”），便于 QA 验证。

### 5. **数据埋点虽不适用，但可考虑本地日志**
- 客户端无服务端埋点，但可增加调试日志开关，便于收集崩溃/性能异常信息（用户自愿上传）。此非必需，但可提升后续优化效率。

## 四、风险再评估
| 风险 | 原缓解措施 | 补充建议 |
|------|------------|----------|
| Xaero 更新导致 Mixin 失效 | 锁定版本范围、CI检测 | 增加运行时的版本检查，若版本不匹配则输出警告并禁用路网叠加，同时记录日志；提供用户手册中说明支持版本。 |
| Xaero 缓存格式变化（P3） | 回退深色网格底图 | 当前 P3 为可选，建议降级为“研究”而非正式开发，避免占用资源。 |
